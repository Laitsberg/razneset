# Правила работы над этим проектом

README рассказывает, **что** здесь лежит; здесь — **как** тут принято работать.
Правила общие с `faryma.stats`: это его младший брат, и читают его те же зрители.

## Главное правило

**Ни одна цифра не попадает в приложение, пока не проверена по данным.**

Прогноз — это обещание. Если пишем «у артиста 12 разносов», их должно быть
ровно 12 и на сайте статистики. Если меняем формулу прогноза — сначала
`npm run backtest`, и в коммит идут цифры до и после. Без этого не менять:
«на глаз стало лучше» здесь уже не раз оказывалось хуже.

## Общий код с сайтом статистики

Шкала, разбор «Артист — Трек», склейка имён и жанров — в `faryma.stats`
(`js/config.js`, `js/aliases.js`, `js/parse.js`). `lib/shared.mjs` грузит их
в песочницу с farymastats.info. **Не копировать их сюда** — разойдутся.

`lib/archive.mjs` пересказывает `build()` из `js/app.js` сайта (сам app.js
в песочницу не загрузить — он рисует страницу). Поменялось правило там —
поменять и тут.

## Перед коммитом

    npm test

    npm run test:app     # после правок в app/, index.html, sw.js
    npm run shots        # и посмотреть глазами снимки в shots/

Проверки ловят «сломано», но не «пусто» и «некрасиво»: при первом
просмотре снимков нашлись вкладки разной высоты и шапка на полэкрана —
ни одна проверка их не заметила бы.

**Проверки не декоративные.** Заводя новую, сломай то, что она стережёт, и
убедись, что она упала. Так при первом же прогоне нашлись две дыры: хвост
«- Remastered 2009» не отрезался, а проверка минусовок пропускала
«(Instinct…)».

## Грабли, на которые уже наступали

* В песочницу `vm` надо передать `URL`, иначе `spotifyId()` молча отдаёт
  пустоту, и все ссылки на Spotify в архиве будто исчезают.
* `const` из песочницы не попадает на объект контекста — доставать через
  `vm.runInContext('SCALE_ORDER', ctx)`; массивы оттуда разворачивать `[...arr]`.
* В регулярках слов с окончаниями (`remaster`, `edit`, `mix`) `\b` после
  корня не срабатывает на «Remastered» — писать `remaster\w*`.
* Шкала — 26 ступеней, а не 30: у «гениально» нет плюсов, у
  «кринж-контента» — минусов. «Гениально+» в архиве — шутка, не оценка.
* Spotify отдаёт имена латиницей, только если **не** ставить
  `accept-language`. Но у артистов без английского написания имя всё равно
  приходит иероглифами — их узнаём только по связке ID.
* Связка «один артист тут, один там — значит, это он» путала издателя с
  композитором (Paradox Interactive → Johan Lindgren). Берём её, только
  когда имена в разных алфавитах или одно содержит другое.
* Одно название трека ничего не значит без совпадения артиста.
* Числа на экране приложения обязаны совпадать с тем, что считает
  `splitLibrary` — браузерная проверка сверяет их напрямую. Своих
  подсчётов в `app/` не заводить.
* Всё, что пришло от Spotify (названия, имена), — через `esc()`: в
  названии трека может оказаться что угодно, вплоть до HTML.
* Сервис-воркер берёт управление страницей только со второй загрузки —
  проверка «без сети» поэтому перезагружает страницу дважды.
* В модели нет времени сборки нарочно: с ним воркфлоу коммитил бы её
  каждые три часа, даже когда архив не менялся.
* Проверка сервера, у которой обработчик падает, должна падать, а не
  висеть: тестовый сервер ловит ошибку и отвечает 500, как настоящий.

## Railway

Сервер — проект `razneset`, сервис `server`, порт задан переменной
`PORT=3000` (на него же смотрит адрес). Ботов faryma.stats в этом проекте
нет и трогать их отсюда незачем.

## Spotify

Треки чужих плейлистов достаём через неофициальный GraphQL веб-плеера
(`lib/spotify.mjs`, в шапке — почему именно так). Если перестало работать,
первым делом смотреть, нашёлся ли свежий отпечаток запроса в коде
open.spotify.com, и жив ли токен на embed-странице.
